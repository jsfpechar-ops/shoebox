## 1. Objective

PR #43's `db` job fails 5 tests in `packages/db/test/with-tenant.db.test.ts` with `password authentication failed for user "app_worker"` (28P01). Migration 0003 creates `app_worker` with LOGIN but no password; the test then connects as `app_worker` with an empty password. That works on the trust-auth sandbox cluster but not on Supabase, which uses scram. The test already reads `WORKER_DATABASE_URL` when set (test lines 19–20, 57). Fix: in the CI `db` job, set a throwaway password on the ephemeral local database right after the first migrate, and export `WORKER_DATABASE_URL`. Nothing in production changes; the real password stays an owner step (gate list).

## 2. Context

See §1. CI-only value on a throwaway local database; it is not a secret.

### Step 1: edit `.github/workflows/ci.yml`

Edit A. Anchor (exact, inside job `db`):

```yaml
      DATABASE_URL: postgresql://postgres:postgres@127.0.0.1:54322/postgres
```

Replace with:

```yaml
      DATABASE_URL: postgresql://postgres:postgres@127.0.0.1:54322/postgres
      # Throwaway password for the ephemeral CI database only (set in the step below).
      WORKER_DATABASE_URL: postgresql://app_worker:ci-local-only@127.0.0.1:54322/postgres
```

Edit B. Anchor (exact):

```yaml

```

```yaml
      - name: Give app_worker a CI-only password (local Supabase uses scram, app_worker has none)
        run: psql "$DATABASE_URL" -c "alter role app_worker password 'ci-local-only'"
      - name: Migrate again (forward-only ledger, must be a no-op)
```
