## 1. Objective

CI `db` fails on PR #71 with `42501 Direct deletion from storage tables is not allowed. Use the Storage API instead.` (`storage.protect_delete()`). The test must opt in to SQL deletes the way Supabase allows, so that RLS on deletes is still tested.

## 2. Context

- Supabase storage migration `0055-prevent-direct-deletes` adds a `BEFORE DELETE … FOR EACH STATEMENT` trigger on `storage.objects` and `storage.buckets`. It raises 42501 unless the session setting `storage.allow_delete_query` is `'true'`. It fires once per DELETE statement, even when 0 rows match.
- The app deletes through the Storage API (BlobStore), so only this test uses SQL deletes. RLS still decides which rows a delete reaches. The setting only switches off the guard.
- `asUser(sql, uid, fn)` (`packages/db/test/rls/helpers.ts`) runs `fn` inside `sql.begin`, so `set_config(…, true)` (transaction-local) works inside it.
- Every DELETE in `packages/db/test/rls/storage.db.test.ts` is in `clearObjects()` and in the last test.

## 4. Steps

1. Replace the function `clearObjects` with:

```ts
  /** Supabase blocks SQL deletes on storage tables unless the transaction opts in (storage 0055). */
  async function clearObjects(): Promise<void> {
    await sql.begin(async (tx) => {
      await tx`select set_config('storage.allow_delete_query', 'true', true)`;
      await tx`delete from storage.objects where bucket_id = ${BUCKET}
        and (name like ${`org/${ORG_A}/%`} or name like ${`org/${ORG_B}/%`})`;
    });
  }
```
